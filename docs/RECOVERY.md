# 復元・更新失敗からの復旧

## アイコンを設定したあとについて

フォルダのアイコンは、変更してもすぐに見た目が切り替わらないことがあります。
そんなときは、少し待ってみてね。
それでも変わらない場合は、デスクトップの何もないところをクリックして、F5キーで表示を更新してみてください。

見た目の遅延と、保存処理のエラーは区別してください。過去のエラー後に表示が変わっても、バックアップ記録が完了しているとは限りません。ログとmanifestを保存し、確認前に繰り返し適用・手動復元・既存ファイル削除をしないでください。表示更新通知／操作ログだけの失敗では、検証済みの設定を自動的に取り消しません。書き込み・属性設定・内容検証・バックアップ確定の失敗は、従来どおり失敗として扱います。

## アイコン適用を元に戻す

適用結果に返る BackupId は、`Backup/<32桁ID>/manifest.json` に対応します。削除せず保存してください。

v0.1.1の通常GUIが新たに作るバックアップは `%LOCALAPPDATA%\AiconFactory\Backup` にあります。以下のようにデータの場所を明示します。旧GUI・PowerShell APIで作成した旧バックアップは移行していないため、その `Backup` の親を `-Root` に指定してください。

```powershell
Import-Module .\App\AiconFactory.psm1 -Force
$dataRoot = Join-Path ([Environment]::GetFolderPath('LocalApplicationData')) 'AiconFactory'
Restore-AiconFactoryIcon -BackupId '実際の32桁ID' -Root $dataRoot -WhatIf
```

- 既存 `.lnk` / `desktop.ini`：元の内容と属性へ戻す
- 今回新規作成した `.lnk`：そのショートカットだけを除去
- フォルダー：保存していた表示用属性も復元
- 適用後に対象が編集された、バックアップが変更された：上書きせず中止

確認後に `-WhatIf` を外します。旧バックアップの場所を新保管庫へ変えるだけでは復元できません。原本・manifestを元の場所に保持します。

失敗時は manifest と original を保全してください。安全確認のため止まったケースで manifest やハッシュを書き換えて強制復元しないでください。原画や ICO は復元処理では削除しません。

## App の更新に失敗した

アプリを閉じ、展開元と配置先には階層が浅く名前の短いローカルフォルダを使用してください。インストーラーは、配布元、新旧の管理ファイル、作業先、バックアップ、失敗時の退避先、復元先、管理情報・ログのパスを既存ファイルの移動前に確認します。Windows PowerShell 5.1で扱える範囲に保つため、完全パスはファイル259文字以下、フォルダ247文字以下（UTF-16単位）に制限します。内部の退避先も含むため、配置先の名前だけでは可否を判断できません。OSの長いパス設定は変更しません。

パスの長さ、アクセス権、使用中のファイルなどを事前確認で検出した場合は、既存ファイルを変更せず停止します。エラーの場所を確認し、使用中のアプリを閉じるか、より短い別の配置先を選んでください。旧ICOを参照する設定先があるため、旧ICOや旧バックアップの移動・削除はしないでください。

入れ替え前に復元用フォルダを作成し、書き込み・移動・削除の確認と復旧記録の作成を行います。入れ替え中に通常の例外が起きた場合は、移動済みの新しいファイルを退避し、旧管理ファイルの復元を試みます。1件の復元が失敗しても他の対象の復元を続け、復元できないものがあればその場所とエラーを表示します。エラーに出る `.aicon-stage-*` と `Backup/Install-*` は調査用に残ります。Library / Backup / Logs 内の既存ユーザーデータとsettings.jsonは更新対象にしません。

更新前の管理ファイルは `Backup/Install-日時-ID/` に保存します。`recovery.json` に対象名が記録されます。初回インストールでは旧管理ファイルはなく、準備時の復旧記録だけが残ります。`Prepared` は準備完了を示し、更新成功や復元成功を示すものではありません。

1. GUI と `aicon` の処理を閉じる
2. エラー文と `Backup/Install-*` を保全する
3. `Library` と `Backup` を別の安全な場所へコピーしてから復旧作業を行う
4. 通常の復元が成功していれば、新しい PowerShell で旧版モジュールを読み込んで確認する
5. 旧版の ZIP がある場合は、README と同様に`Root/_package` 内の新しいフォルダーへ展開して、同じ `-Root` へ再インストールする

強制終了・停電、事前確認後の権限変更・別プロセスによる変更・ディスク障害などでは、自動復旧を保証しません。管理情報が欠けているとインストーラーは上書きせず停止します。手動作業が必要な場合、`recovery.json` の対象と実ファイルを照合し、**App・起動スクリプト・同梱文書・管理情報のみ**を扱ってください。Library や Backup 全体を旧版で上書きしないでください。

## アイコンが変わって見えない

対象を開き直す、F5 で更新する、ショートカットのプロパティで IconLocation の参照を確認する、の順で確認します。実際の ICO が移動・削除されている場合は参照を直す必要があります。Explorer の強制終了やキャッシュ削除は本ツールでは行いません。

## アンインストール

v0.1.1の通常GUIが利用する `%LOCALAPPDATA%\AiconFactory` はアプリ本体と別の場所です。ICOを参照しているフォルダ・ショートカットがある間は、このデータ領域を削除しないでください。アプリの移動・更新では削除する必要はありません。

先に必要なアイコン設定を復元し、必要な Library / Backup / Logs を保存します。その後、専用インストールフォルダーを手動で削除してください。ZIP 展開元も不要なら別途削除できます。PATH や Profile の後片付けは不要です。

インストール開始時の `.aicon-install.lock` は正常終了・通常のエラーでは解放されます。強制終了後に残った場合は、別のインストールが動いていないことと復元先の内容を確認してから、そのロックファイルだけを手動で削除してください。実行中のロックを削除して同時更新を始めないでください。
